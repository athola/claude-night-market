### The Fable correction

Yesterday's bootstrap added `fable` to the vocabulary from the harness
model roster alone, without reading the model card, and placed it as a
Creative tier at roughly Sonnet cost. The card says otherwise: Fable 5
is the most capable widely released model, at twice Opus 5's input
price, with slower latency, built for long-running agents.

This is the exact failure the research protocol warns about. Updating
from release notes alone changes syntax without changing judgment, and
a repo ends up pinning a new model to whatever tier felt adjacent. The
mandatory-model-card rule earned itself on its first real run.

## Tooling corrections found by running the workflow

Three defects in the tooling surfaced only once it was driven against a
real migration rather than a bootstrap.

### `record_migration` recorded a no-op delta

The first write of this migration produced `from.harness: 2.1.220` and
`to.harness: 2.1.220` for a run covering 2.1.80 to 2.1.220. The function
derived `from` off the previous migration's `to`, and the bootstrap
record had over-claimed. Nothing cross-checked it against the ledger's
own state.

The fix adds `snapshot_state(ledger)`, taken before the run mutates
anything, and passes it as an explicit `from_state`. The signature moved
to `record_migration(ledger, migration, from_state=None)`. The old test
asserted `from == to` and passed, so the test encoded the bug; it has
been replaced with one that fails on a no-op delta.

### The dated-ID ratchet was counting build artifacts

Of the 124 findings the ratchet measured, 80 were `.mypy_cache` entries
for the vendored `anthropic` SDK's model type stubs. The ratchet moved
when someone reran mypy. Tool caches and vendored packages
(`.mypy_cache`, `.pytest_cache`, `.ruff_cache`, `.tox`, `.eggs`,
`site-packages`, `htmlcov`) are now skipped.

### Migration reports counted against their own ratchet

A report documenting a retirement must name the retiring model, so every
run of this workflow raised the ratchet by one. `migrations/` is now
skipped, on the same principle the repo's prose rules use to exempt
historical changelog entries.

## Second pass: live pins in executable code

Reviewed on request after the first pass flagged them. Three files, four
distinct defects, all with tests written first.

### `phantom/cost.py`: pricing was wrong, not merely stale

This table feeds `CostTracker.budget_exceeded`, so wrong rates mean the
budget guard stops at the wrong number.

| Entry | Was | Published | Effect |
|-------|-----|-----------|--------|
| `claude-opus-4-6` | $15 / $75 | $5 / $25 | Overstated 3x |
| `claude-haiku-4-5-20251001` | $0.80 / $4.00 | $1 / $5 | Understated 25% |
| `claude-opus-5` | absent | $5 / $25 | Fell to $3 / $15 default |
| `claude-fable-5` | absent | $10 / $50 | Fell to default, understated 3.3x |

Opus 4.6 carried Opus 4.1's rate. Current models were absent entirely,
so a Fable 5 run burned 3.3x its budget before the guard noticed.

The fallback rate moved from Sonnet's $3 / $15 to the highest current
rate, $10 / $50. A budget guard has to fail toward stopping early, and
the old default guaranteed the opposite for anything above Sonnet.
`DEPRECATED_MODELS` excludes Opus 4.1 from that calculation so a rate
retiring on 2026-08-05 does not set the floor for every unknown model.

A pre-existing test asserted a single iteration costs under $1 while
passing no model, so it was silently asserting a property of the
fallback rate. It now pins `claude-sonnet-5` and tests the arithmetic.

### `phantom/loop.py`: two model IDs that never existed

`TOOL_VERSIONS` was keyed by `claude-opus-4-5-20250620` and
`claude-sonnet-4-5-20250514`. The published IDs are `20251101` and
`20250929`. A real Sonnet 4.5 call matched no prefix and fell through to
`computer_20251124` instead of the `20250124` tools it expects.

The existing test asserted against the invented date, so it passed while
the real model took the wrong path. The fallback itself is correct and
stays: an unrecognized model should get the newest tools.

`LoopConfig.model` moved from `claude-sonnet-4-6` to `claude-sonnet-5`.
Same tier, same list price, current generation.

### `conjure/war_room/config.py`: names that encode a version

`CLAUDE_OPUS_48` and `CLAUDE_SONNET_46` named the generation in the
constant. Updating the value alone would leave `CLAUDE_OPUS_48 =
"claude-opus-5"`, a constant whose name contradicts it, so the rename
was forced rather than chosen. The constants are now `CLAUDE_OPUS`,
`CLAUDE_SONNET`, and `CLAUDE_HAIKU`, pointing at Opus 5, Sonnet 5, and
Haiku 4.5, with `experts.py`, `orchestrator.py`, and the test updated.

This moves the war-room panel's Supreme Commander from Opus 4.8 to Opus
5 and its Chief Strategist from Sonnet 4.6 to Sonnet 5.

### Ratchet raised, deliberately

`ratchets.dated_ids_backlog` went from 44 to **51**. The increase is the
pricing table gaining explicit legacy entries: to price Opus 4.6 you
have to name Opus 4.6.

This exposes a limit of the detector worth stating plainly. It counts
*mentions* of dated IDs, not *pins*. A lookup table keyed by legacy
model IDs is inherently mention-heavy and does not rot in the dangerous
sense. The pins that actually rot are defaults and selections, and those
are exactly what this pass removed. The number went up while the risk
went down.

## Follow-ups

- **Live model pins in source.** `plugins/phantom/src/phantom/loop.py`,
  `cost.py`, and `plugins/conjure/scripts/war_room/config.py` pin dated
  model IDs in executable code. These rot on retirement and changing
  them alters behavior, so each needs its own reviewed change.
- Consider registering the `Notification` hook. Several plugins already
  spawn background agents and currently learn nothing when one finishes.
- Consider whether any `SessionStart` hook branching on `source` needs
  to handle `"fork"`. A forked session currently takes the resume path.
- Sonnet 5 introductory pricing ends 2026-08-31. The cost column in the
  matrix carries a note; revisit it then.
- Opus 4.1 retires 2026-08-05. No live pin depends on it, so this is a
  watch item rather than work.
- `pyproject.toml` `norecursedirs` replaced pytest's default ignore list
  instead of extending it, which made the hypothesis plugin warn on
  every run. The missing defaults are now listed explicitly.
